# Cross-Subject Adaptation Guide

Automatically adjust analysis framework and output structure by subject.

## STEM (Science, Technology, Engineering, Math, Agriculture)

### Knowledge Organization
- **Formula/Theorem Library**: Original expression + conditions + symbol meanings + derivation outline + common variants + error warnings
- **Experiment Method Card**: Purpose → Principle → Equipment → Steps → Precautions → Errors → Data processing
- **Calculation Model**: Model name → Conditions → Core formula → Typical variations → Common errors

### Question Characteristics
- **MCQ**: Concept discrimination + quick estimation + limit/special case verification
- **Fill-in**: Precise terms, units, symbols, sign conventions
- **Calculation**: Must show "Set → List → Solve → Verify → Answer" five steps
- **Proof**: Work backwards from conclusion, find intermediate lemmas

### Output Preferences
1. Complete derivation (no skipped steps)
2. Unit conversion table (after cover)
3. Formula quick-reference sheet (single A4 page)
4. Error attribution labels (calculation/concept/reading/formula)

### Biology/Agriculture Special Handling
- Latin names in italics, genus capitalized
- Classification keys in dichotomous key structure
- Physiological indicators with normal ranges, methods, units
- Molecular experiments with reagent concentrations, temperatures, times

## Humanities (Literature, History, Philosophy, Law, Education)

### Knowledge Organization
- **Timeline Card**: Period → Background → Key figures → Core claims → Representative works → Historical significance → Before/after relationships
- **Concept Comparison Matrix**: Dimension vs Concept A vs Concept B
- **Essay Evidence Bank**: Classical evidence + Historical evidence + Contemporary evidence (3 each)

### Question Characteristics
- **Term definition**: "Definition + Proposer + Core content + Significance" four-part structure
- **Short answer**: Opening sentence + points (①②③) + closing sentence, each point "claim + example"
- **Essay**: "Intro-Body-Conclusion", body points use "First/Second/Third/Finally"
- **Material analysis**: Summarize material → Connect theory → Analyze and evaluate

### Output Preferences
1. Academic expression with discipline terminology
2. Logical connectors (First/Second/Therefore/In conclusion)
3. Citation format: Name (Year) or footnotes
4. Theory-evidence integration: every claim backed by material

### Special Handling
- **Law**: Statute text + Judicial interpretation + Typical cases
- **Education**: Theorist + Experiment + Real-world application
- **Journalism**: 5W1H + Communication theory integration

## Medical

### Knowledge Organization
- **Disease Card**: Name → Definition → Etiology → Pathology → Clinical manifestations → Auxiliary tests → Diagnostic criteria → Differential diagnosis → Treatment → Prognosis → Prevention → Mnemonic
- **Drug Card**: Name → Category → Mechanism → Indications → Contraindications → Side effects → Antidote → Interactions → Special populations → Memory anchor
- **Anatomy Memory**: 3D positioning + Functional connections (artery → vein → nerve) + Clinical correlation

### Question Characteristics
- **Type A**: Watch for "first choice", "most common", "most specific"
- **Case series**: Diagnosis → Evidence → Further tests → Treatment
- **Memory-intensive**: Drug = Mechanism → Indications → Contraindications → Side effects → Antidote

### Output Preferences
1. Comparison tables: Normal vs Abnormal, Disease A vs B
2. Flowcharts: Diagnostic workflow, treatment decision trees
3. Mnemonics: Anatomy structures, drug categories, disease classifications
4. Case analysis template: Chief complaint → History → Physical → Tests → Diagnosis → Treatment

### Special Handling
- Normal values with units and gender/age differences
- English terms with full name on first appearance, abbreviations later
- Imaging/ECG described in text ("boot-shaped heart", "ST-segment elevation")

## Coding / Technical

### Knowledge Organization
- **Algorithm Card**: Name → Type → Core idea → Template code → Complexity → Applicable scenarios → Non-applicable → Examples → Common errors → Variations
- **Concept Card**: Concept → Definition → Lay explanation → Core mechanism → Use cases → Pros/cons → Comparison → Versions → Interview questions
- **System Design Quick Reference**: QPS → Storage → Schema → Cache → Sharding → Consistency → Degradation

### Question Characteristics
- **Algorithm**: Brute force → Optimize → Optimal, analyze time/space complexity
- **Concept**: What → Why → How → Pros/cons → Use cases → Version differences
- **System design**: 4S method (Scenario → Service → Storage → Scale)

### Output Preferences
1. Runnable code + test cases (normal + boundary + extreme)
2. Complexity tables
3. Flowcharts, state transition diagrams, memory layout diagrams

### Special Handling: Certifications
- Objective questions: Precise official definitions
- Case analysis: Problem identification → Root cause → Solution → Prevention
- Configuration: Accurate commands, attention to modes (user/privileged/config)
